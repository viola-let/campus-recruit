## 4. M1｜数据与认证基础

### 4.1 目标

跑通“建库 → 初始化账号 → 登录 → 按角色进入不同导航 → 退出”的最小闭环。

### 4.2 产出文件

| 文件 | 内容 |
|---|---|
| `core/config.py` | 路径常量、`Role` / `ReviewStatus` / `JobStatus` / `ApplicationStatus` 枚举、会话 key、上传限制 |
| `core/db.py` | `get_connection()`、`init_db()`、`query_one()`、`query_all()`、`execute()` |
| `core/security.py` | `hash_password()`、`verify_password()`、`validate_upload()`、`safe_filename()` |
| `core/auth.py` | 学生注册、企业注册、登录、`require_role()` |
| `scripts/init_db.py` | 建表 + 创建管理员（邮箱/密码来自命令行参数或环境变量） |
| `scripts/seed_demo.py` | 演示数据：管理员、1 名已核查学生、1 家双审通过企业、1 家待审企业、若干职位与投递 |
| `app.py` | 会话初始化、角色路由、公共侧边栏、退出登录 |
| `views/auth/login.py` | 登录 + 学生/企业注册表单 |
| `tests/test_security.py` | T-01、T-02、T-10 |
| `tests/test_auth.py` | T-03、T-04 |
| `tests/conftest.py` | 临时数据库夹具 |

### 4.3 实现要点

1. 先写 `core/db.py`，用 `CREATE TABLE IF NOT EXISTS` 建 6 张表。
2. `init_db.py` 支持参数：`--db`、`--admin-email`、`--admin-password`；不把密码写死在代码里。
3. 密码使用 PBKDF2-HMAC-SHA256 + 16 字节盐 + 600,000 次迭代。
4. 登录成功只把 `id`、`email`、`role`、`display_name` 写入 `st.session_state["auth_user"]`。
5. `app.py` 只调用一次 `st.navigation`，并执行 `page.run()`。
6. 未登录时导航只有登录页；登录后按角色构建页面字典。
7. 退出登录清空 `st.session_state` 并 `st.rerun()`。

### 4.4 验收标准

- 首次运行 `python scripts/init_db.py` 后生成 `data/app.db`，6 张表齐全。
- 管理员可登录并进入管理端占位首页。
- 学生、企业可自助注册；重复邮箱被拒绝。
- 三种角色登录后看到的导航项互不越界。
- 退出后无法通过浏览器后退恢复操作。
- T-01、T-02、T-03、T-04、T-10 全部通过。

### 4.5 验证命令

```powershell
python scripts/init_db.py --admin-email admin@example.com --admin-password "ChangeMe123"
python scripts/seed_demo.py
streamlit run app.py
pytest -q tests/test_security.py tests/test_auth.py
```

### 4.6 完成标志

V1 通过，提交：`feat: 完成数据库、认证与三角色路由`

## 5. M2｜学生端

### 5.1 目标

学生可以维护简历、上传附件、搜索职位、投递，并查看反馈。

### 5.2 产出文件

| 文件 | 内容 |
|---|---|
| `services/students.py` | `save_resume()`、`get_resume()` |
| `services/jobs.py` | `search_jobs()`（先实现只读检索） |
| `services/applications.py` | `apply_to_job()`、`list_my_applications()` |
| `views/student/home.py` | 简历状态、投递统计、快捷入口 |
| `views/student/resume.py` | 简历表单 + 附件上传 + 送审 |
| `views/student/jobs.py` | 关键词 / 城市 / 类型筛选 + 投递 |
| `views/student/applications.py` | 投递记录与反馈 |
| `tests/test_services.py` | T-05、T-06（学生部分） |

### 5.3 实现要点

1. 简历保存后状态为 `PENDING`；修改已核查简历同样回到 `PENDING`。
2. 上传先校验再落盘：扩展名白名单、≤ 5 MB、UUID 文件名、目录边界校验。
3. 职位查询只返回 `APPROVED` 且未关闭的职位，推荐优先、时间倒序，`LIMIT 100`。
4. 投递前依次校验：简历 `VERIFIED` → 职位 `APPROVED` → 未重复投递。
5. 投递时写 `resume_snapshot`（JSON）与 `resume_file_snapshot`。
6. 页面只调用服务函数，不写 SQL。
7. 列表为空时显示引导文案，不显示空白页。

### 5.4 验收标准

- 学生可保存简历并看到 `PENDING` 状态。
- 非法文件被拒绝，合法文件保存到 `uploads/resumes/`。
- 未核查简历无法投递，页面与服务层双重拦截。
- 同一职位第二次投递被拒绝。
- 投递后“我的投递”立即出现记录。
- 企业更新状态后，学生刷新可见最新反馈。
- T-05、T-06 通过。

### 5.5 验证命令

```powershell
pytest -q tests/test_services.py
streamlit run app.py
```

手工路径：学生登录 → 保存简历 → 管理员在数据库中将会话学生简历置为 `VERIFIED`（或用 seed 账号）→ 搜索职位 → 投递 → 查看记录。

### 5.6 完成标志

V2 通过，提交：`feat: 完成学生端简历、职位检索与投递闭环`

## 6. M3｜企业端

### 6.1 目标

企业可以维护资料、查看双审核状态、发布职位、筛选候选人并处理投递。

### 6.2 产出文件

| 文件 | 内容 |
|---|---|
| `services/companies.py` | `upsert_profile()`、`get_profile()`、`can_publish_job()` |
| `services/jobs.py` | `create_job()`、`update_job()`、`close_job()`、`reopen_job()`、`list_company_jobs()` |
| `services/applications.py` | `list_job_candidates()`、`update_status()`、`download_resume()` |
| `views/company/home.py` | 审核状态、职位数、待处理候选人数 |
| `views/company/profile.py` | 企业资料 + 营业执照 + HR 资料 |
| `views/company/jobs.py` | 发布 / 编辑 / 关闭 / 重提 |
| `views/company/candidates.py` | 按职位 / 学校 / 专业 / 状态筛选 + 状态更新 |
| `tests/test_services.py` | T-07、T-08（企业部分） |

### 6.3 实现要点

1. 企业注册后自动生成 `PENDING` 企业资料，首次登录引导完善。
2. `can_publish_job()` 同时检查 `status == APPROVED` 与 `hr_status == APPROVED`。
3. 职位编辑、被拒重提、关闭后重开，状态均回到 `PENDING`（见 Spec BR-02）。
4. 候选人查询通过 `application → job → company_id` 校验归属。
5. 投递状态严格按 Spec 5.3 的允许表流转；拒绝时反馈必填。
6. 附件下载使用投递快照路径，并校验路径位于 `uploads/resumes/`。

### 6.4 验收标准

- 双审未通过时发布入口禁用，服务层同样拒绝。
- 发布职位后状态为 `PENDING`，学生端不可见。
- 企业只能看到本公司职位的投递。
- 状态流转非法时被拒绝，合法时更新时间与反馈。
- 可下载候选人投递时的附件。
- T-07、T-08 通过。

### 6.5 验证命令

```powershell
pytest -q tests/test_services.py
streamlit run app.py
```

手工路径：企业登录 → 完善资料 → 管理员通过双审（M4 完成后）→ 发布职位 → 管理员通过职位 → 学生投递 → 企业筛选并更新状态。

### 6.6 完成标志

V3 通过，提交：`feat: 完成企业端资料、职位与候选人管理`

## 7. M4｜管理端

### 7.1 目标

管理员完成四层审核，平台首页展示待办与核心指标。

### 7.2 产出文件

| 文件 | 内容 |
|---|---|
| `services/companies.py` | `review_license()`、`review_hr()`、`set_company_active()` |
| `services/jobs.py` | `review_job()`、`set_featured()` |
| `services/students.py` | `review_resume()` |
| `services/admin.py` | `dashboard_counts()`、`pending_queues()` |
| `views/admin/home.py` | 6 个指标 + 跳转 |
| `views/admin/companies.py` | 资质审核 / HR 审核两个页签 |
| `views/admin/jobs.py` | 职位审核 + 推荐 |
| `views/admin/resumes.py` | 简历核查 |
| `tests/test_services.py` | T-09（审核权限与并发） |

### 7.3 实现要点

1. 所有审核在事务内重新读取状态，仅 `PENDING` 可处理。
2. 每次审核写 `review_logs`，记录审核人、决策、理由、时间。
3. 拒绝理由必填；通过可不填。
4. 推荐只允许 `APPROVED` 职位。
5. 概览统计使用单条聚合 SQL，避免多次查询。
6. 管理员页面不提供学生/企业资料的编辑入口，只做审核与启用/停用。

### 7.4 验收标准

- 四类待审记录均可在对应页面处理。
- 已处理记录再次提交审核会被拒绝并提示。
- 拒绝理由为空时无法提交。
- 企业双审通过后可发布职位；职位通过后学生可见。
- 简历核查通过后学生可投递。
- 概览数字与列表数量一致。
- T-09 通过。

### 7.5 验证命令

```powershell

```

## 7.5 M4.5｜REST API 适配层

### 7.5.1 目标

在 `services/` 之上增加 FastAPI 适配层，输出可调用的 REST 接口与 OpenAPI 3.1 契约，业务规则与 UI 完全一致。

### 7.5.2 产出文件

| 文件 | 内容 |
|---|---|
| `api/main.py` | FastAPI 实例、CORS、路由注册、`/health` |
| `api/deps.py` | Bearer Token 解析、当前用户、角色守卫 |
| `api/schemas.py` | Pydantic 请求 / 响应模型 |
| `api/routes/auth.py` | 注册、登录、`/auth/me` |
| `api/routes/students.py` | 简历、投递记录 |
| `api/routes/companies.py` | 企业资料、职位管理、候选人 |
| `api/routes/jobs.py` | 职位检索、投递 |
| `api/routes/admin.py` | 统计、待办、四层审核 |
| `scripts/export_openapi.py` | 导出 `api/openapi.json` |
| `tests/test_api.py` | TestClient 接口测试 |

### 7.5.3 实现要点

- 所有路由只调用 `services/`，禁止在 `api/` 写 SQL 或复制业务判断。
- JWT：HS256，Payload 含 `sub` / `role` / `iat` / `exp`（8 小时），密钥取 `API_JWT_SECRET`。
- CORS 只允许 `http://localhost:8501`。
- `BusinessError` 统一映射为 `400/404/409`，响应体 `{code, message}`。

### 7.5.4 验收标准

- `uvicorn api.main:app --port 8000` 可启动，`/health` 返回 200。
- `/docs` 可交互，`/openapi.json` 为 OpenAPI 3.1。
- 无 Token → 401；角色不符 → 403。
- 重复投递、未过审职位投递等规则与 UI 一致。
- `api/openapi.json` 已导出且与运行时一致。

### 7.5.5 验证命令

```powershell
uvicorn api.main:app --port 8000
python scripts/export_openapi.py
pytest -q tests/test_api.py
```

### 7.5.6 完成标志

V4.5 通过，提交：`feat: 增加 FastAPI REST 适配层与 OpenAPI 契约`

> 部署口径：Community Cloud 只运行 Streamlit，公网不提供 REST；REST 仅本地或自建 VPS/Docker 可用。

## 10. 每个里程碑的固定检查动作

每完成一个里程碑，按顺序执行：

```powershell
ruff format .
ruff check .
python -m compileall .
pytest -q
git add <本里程碑文件>
git commit -m "<type>: <简述>"
```

| 检查 | 不通过时 |
|---|---|
| 格式化失败 | 先 `ruff format .` 再复检 |
| 静态检查失败 | 修复后重新运行，禁止跳过 |
| 编译失败 | 定位语法/导入错误 |
| 测试失败 | 修复代码或补测试，禁止删除测试规避 |
| 手工路径阻塞 | 记录问题，修复后再提交 |
