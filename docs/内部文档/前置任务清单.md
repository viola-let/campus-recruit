### 2.2 Python 版本要求

**结论：安装 Python 3.12.x（64 位）。**

依据：

- Streamlit 1.67.0 官方安装文档明确支持 **Python 3.11 至 3.15**。
- Streamlit 1.66.0 起，因 Python 3.10 已结束生命周期（EOL），**不再支持 3.10 及以下**。
- 推荐 3.12 的原因：处于官方支持区间内、生态兼容性最稳、Windows 安装包成熟；3.13/3.14/3.15 也可运行，但初学者遇到第三方兼容问题时排查成本更高。

| 项 | 执行标准 |
|---|---|
| 安装来源 | 只从 Python 官网 <https://www.python.org/downloads/> 下载 |
| 版本 | 3.12.x（64-bit） |
| 安装选项 | 勾选 `Add python.exe to PATH`；勾选 `pip` |
| 禁止 | 不使用 Microsoft Store 的 Python 占位程序；不使用来源不明的绿色版 |

**验证命令：**

```powershell
python --version
python -c "import sys; print(sys.executable); print(sys.version_info[:3])"
```

**通过标准：**

- 输出 `Python 3.12.x`；
- `sys.executable` 指向真实安装路径（不是 `WindowsApps`）；
- 主版本号为 3，次版本号为 11-15 之间。

| 项 | 执行标准 |

## 3. P1-P2｜Streamlit 版本选型与依赖约束

### 3.1 Streamlit 版本选型依据

| 维度 | 结论 | 依据 |
|---|---|---|
| 版本 | `streamlit==1.67.0` | 2026-11-05 发布的官方最新稳定版 |
| Python 兼容 | 3.11-3.15 | 官方 2026 release notes 与安装文档 |
| 多页应用 | 使用 `st.Page` + `st.navigation` | 官方明确为“首选（preferred）”的多页方案 |
| 测试 | `streamlit.testing.v1.AppTest` + pytest | 官方原生应用测试框架 |
| 配置 | 项目级 `.streamlit/config.toml` | 官方配置优先级中的 per-project / script-level 配置 |

**为什么不选 `pages/` 目录方案？**
`pages/` 是更简单的旧方案；`st.Page` + `st.navigation` 是官方当前推荐方案，能按角色动态生成导航，正好匹配本项目“学生 / 企业 / 管理员”三端权限模型。

### 3.2 依赖分层与版本约束规则

| 依赖类型 | 文件 | 约束规则 | 理由 |
|---|---|---|---|
| 运行时依赖 | `requirements.txt` | 使用 `==` 精确锁定 | 保证任何机器安装出完全一致的运行环境 |
| 开发工具 | `requirements-dev.txt` | 使用 `>=` 最小版本 | 工具升级风险低，避免频繁改锁文件 |
| 标准库 | 不写入依赖文件 | 直接使用 | `sqlite3`、`hashlib`、`hmac`、`uuid`、`pathlib`、`csv`、`datetime` 均随 Python 提供 |
| 传递依赖 | 不手动写 | 由 pip 解析 | 手动锁传递依赖会显著增加初学者维护成本 |

### 3.3 当前依赖清单

| 包 | 版本约束 | 用途 | 官方/通用依据 |
|---|---|---|---|
| `streamlit` | `==1.67.0` | Web 应用框架 | Streamlit 官方 |
| `fastapi` | `==0.163.2` | REST 适配层，自动生成 OpenAPI 3.1 | FastAPI 官方 |
| `uvicorn` | `==0.54.0` | ASGI 运行服务器 | FastAPI 官方推荐 |
| `pyjwt` | `==2.15.1` | JWT 签发与校验 | PyJWT 官方 |
| `pytest` | `>=8.0` | 运行自动化测试 | Streamlit 官方 AppTest 文档推荐 |
| `ruff` | `>=0.6` | PEP 8 检查与格式化 | Python 社区通用工具 |
| `httpx` | `>=0.27` | FastAPI `TestClient` 依赖 | FastAPI 官方测试文档 |
| `sqlite3` | 标准库 | 本地关系型数据库 | Python 官方 |
| `hashlib` / `hmac` | 标准库 | 密码哈希与恒定时间比较 | Python 官方 |

## 5. P5｜编码规范

### 5.1 基础规范（PEP 8 + 社区共识）

| 项 | 标准 |
|---|---|
| 缩进 | 4 个空格，禁止 Tab |
| 行宽 | 88 字符（ruff 默认，与 Black 一致） |
| 编码 | UTF-8 |
| 空行 | 顶层定义之间 2 个空行，类内方法之间 1 个空行 |
| 尾随空格 | 禁止 |
| 文件结尾 | 保留一个换行 |
| 引号 | 统一双引号（ruff format 自动处理） |

### 5.2 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 模块 / 包 | 小写 + 下划线 | `applications.py` |
| 函数 / 变量 | 小写 + 下划线 | `create_application` |
| 类 | 大驼峰 | `ReviewStatus` |
| 常量 | 全大写 + 下划线 | `MAX_UPLOAD_MB` |
| 私有函数 | 前缀单下划线 | `_hash_password` |
| 布尔值 | `is_` / `has_` / `can_` 开头 | `is_active`、`can_publish_job` |
| 数据库表 / 字段 | 小写 + 下划线，表名复数 | `applications.resume_id` |

### 5.3 import 规范

顺序固定，组间空一行：

```python
# 1. 标准库
from pathlib import Path
import sqlite3

# 2. 第三方库
import streamlit as st

# 3. 本项目
from core.db import get_connection
from services.jobs import list_open_jobs
```

禁止 `from module import *`；禁止在函数内部做无必要的 import。

### 5.4 Streamlit 专项约定（依据官方文档）

| 约定 | 说明 | 官方依据 |
|---|---|---|
| 入口唯一 | 只有 `app.py` 调用 `st.navigation`，且每次运行只调用一次，然后执行 `pg.run()` | Define multipage apps with st.Page and st.navigation |
| 全局页面配置 | `st.set_page_config` 只在 `app.py` 调用一次 | 同上 |
| 页面脚本 | `views/**/*.py` 直接写顶层语句，不写 `if __name__ == "__main__"` | 页面由 `st.navigation` 执行 |
| 会话状态 | 所有 key 统一定义在 `core/config.py` 的常量中，并在 `app.py` 初始化 | Session State 官方文档 |
| 缓存 | 读多写少的数据用 `st.cache_data`；全局资源用 `st.cache_resource`；**写操作绝不缓存** | Caching 官方文档 |
| 表单 | 多个输入 + 一个提交按钮时使用 `st.form`，减少无效重跑 | 官方 API 文档 |
| 重跑 | 写操作成功后调用 `st.rerun()` 刷新页面 | 官方 API 文档 |
| 安全 | 不使用 `unsafe_allow_html=True` 渲染用户输入 | 官方 API 文档安全提示 |
| 异常 | 业务校验失败用 `st.warning` / `st.error` 提示，不把异常堆栈直接展示给用户 | 官方最佳实践 |

### 5.5 注释与文档字符串

- 注释解释“为什么”，不重复“代码在做什么”。
- 每个 `services/` 函数写一行 docstring，说明入参、返回值、可能抛出的业务异常。
- 面向初学者的关键流程可写中文注释；标识符一律使用英文。
- 禁止保留无用的注释代码块。

### 5.6 类型注解

- 函数参数与返回值**建议**加类型注解，尤其是 `services/` 和 `core/`。
- 不强制引入 mypy，避免增加初学者的工具负担。

```python
def get_user_by_email(email: str) -> dict | None: ...
```

### 5.7 错误处理

| 场景 | 做法 |
|---|---|
| 用户输入错误 | 返回明确的业务错误信息，页面用 `st.error` 展示 |
| 数据库唯一约束冲突 | 捕获 `sqlite3.IntegrityError`，转换为业务错误 |
| 文件不存在 / 越权访问 | 记录日志，向用户展示统一提示，不泄露路径 |
| 未知异常 | 只记录到服务端日志，页面展示“操作失败，请稍后重试” |

### 5.8 质量门禁命令

```powershell
ruff format .          # 格式化
ruff check .           # 静态检查
python -m compileall . # 语法编译检查
pytest                 # 自动化测试
```

四项全部通过，才允许合并代码。

| `main` | 始终保持可运行 | — |
| `feat/*` | 新功能 | `feat/student-apply` |
| `fix/*` | 缺陷修复 | `fix/job-review-permission` |
| `docs/*` | 文档 | `docs/spec-v1` |
| `chore/*` | 工程配置 | `chore/init-scaffold` |

规则：分支从 `main` 拉出，完成后合并回 `main`，合并前必须通过 5.8 的质量门禁。

### 6.3 提交信息规范（Conventional Commits）

格式：`<type>: <简述>`

| type | 含义 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修复缺陷 |
| `docs` | 文档 |
| `test` | 测试 |
| `refactor` | 重构（不改变行为） |
| `chore` | 构建 / 工具 / 依赖 |
| `style` | 格式调整 |

示例：`feat: 学生投递职位并生成投递记录`

### 6.4 版本标签

| 标签 | 含义 |
|---|---|
| `v0.1.0` | 阶段 0-4 文档与脚手架完成 |
| `v0.2.0` | 登录与三角色路由可用 |
| `v0.3.0` | 学生端 + 企业端主流程可用 |
| `v1.0.0` | 三端 + 四层审核 + 测试全部通过 |

### 6.5 禁止提交的内容

- `.venv/`
- `.streamlit/secrets.toml`
- `data/*.db`
- `uploads/**` 中的真实简历与营业执照
- 任何包含真实密码、密钥、个人信息的文件

## 7. P4｜配置与安全规范

### 7.1 配置文件

| 文件 | 作用 | 是否提交 |
|---|---|---|
| `.streamlit/config.toml` | 主题、服务端、浏览器行为 | 是 |
| `.streamlit/secrets.toml` | 本地密钥（本项目 MVP 不强制使用） | **否** |
| `pyproject.toml` | pytest / ruff 配置 | 是 |

配置优先级（官方，从低到高）：全局配置 → 项目配置 → 脚本级配置 → 环境变量 → 命令行参数。项目中统一使用 `.streamlit/config.toml`，不混用多套配置。

### 7.2 安全底线

| 风险 | 规范 |
|---|---|
| 密码存储 | 使用 `hashlib.pbkdf2_hmac("sha256", ...)` + 每用户随机盐；用 `hmac.compare_digest` 校验；**绝不存明文** |
| SQL 注入 | 一律使用参数化查询 `?` 占位符，禁止字符串拼接 SQL |
| 文件上传 | 扩展名白名单（`pdf`、`docx`）、单文件 ≤ 5 MB、服务端生成 UUID 文件名、保存路径必须在 `uploads/` 内 |
| 越权访问 | 每个服务层写操作都校验“当前用户角色 + 资源归属” |
| 路径穿越 | 用户提供的文件名只用于展示，不参与拼接保存路径 |
| 敏感信息 | 不在代码、日志、Git 中写入真实密码或密钥 |
