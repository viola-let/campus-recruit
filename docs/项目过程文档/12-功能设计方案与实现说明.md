## 1. 背景与目标

v1.1 解决了「岗位信息是否真实、检索是否高效」的问题，但仍存在两类信息差：

1. 求职者只能看到企业官方品牌介绍，缺少员工视角的真实信息；
2. 企业端只有候选人列表，缺少招聘效果量化、候选人匹配排序与雇主品牌运营能力。

v1.2 在现有三角色、四层审核与可解释推荐的基础上，新增企业文化交流、企业评分、急招专区、小任务兼职与三项企业端能力，并保持「services 不依赖 Web 层、页面单文件 ≤ 250 行、先审后发」的工程约束。

---

## 2. 三项需求的评估与修正结论

| # | 需求 | 评估 | 主要风险 | 结论 |
|---|---|---|---|---|
| 1 | 企业文化交流区 | 价值高，直击信息差 | 身份无法验证、匿名滥用、内容合规 | 采纳，增加身份标签、先审后发、企业回应权 |
| 2 | 离职 / 实习人员评分 | 合理，可反哺推荐排序 | 刷分、恶意差评、新企业被误伤 | 采纳，改为多维度评分 + 最小样本 + 小权重 |
| 3a | 急招岗位专区 | 合理，场景拆分正确 | 标签通胀、虚假紧迫营销 | 采纳，急招为带到期时间的受控状态 |
| 3b | 小任务兼职 | 有条件采纳 | 刷单、押金、垫付等灰产 | 采纳，平台不碰资金 + 关键词拦截 + 先审后发 |

## 3. 企业文化交流区（FR-C）

### 3.1 使用规则

| 项 | 规则 |
|---|---|
| 发布资格 | 登录学生；简历已核查时经验帖标记「已核验」，否则标记「自述」 |
| 任职状态 | 在职 / 曾任职 / 实习过 / 未任职；未任职 **只能提问**，不能发布内部经验 |
| 匿名 | 前台匿名、后台实名；匿名帖统一显示「匿名用户」 |
| 频率 | 同一学生对同一企业 7 天内最多 1 条经验帖；全站每日最多 3 条 |
| 字数 | 标题 5-60 字；经验帖正文 ≥ 30 字；提问正文 ≥ 10 字 |
| 审核 | 先审后发；管理员在「内容审核 → 文化帖」通过或拒绝 |
| 企业回应 | 仅本企业可对已通过帖子回应 1 次，5-500 字 |
| 内容红线 | 命中刷单、押金、垫付、返利、拉人头等黑名单直接拒绝 |

### 3.2 页面入口

- 学生端「校园社区 → 企业文化」：浏览企业口碑、评分摘要、发布经验 / 提问、查看我的发布；
- 学生端「企业主页」：品牌信息 + 在招职位 + 员工分享 + 员工评分聚合；
- 企业端「企业社区」：员工分享与官方回应、收到的评分；
- 管理端「内容审核」：文化帖审核队列。

## 4. 企业评分机制（FR-E）

### 4.1 评分维度与规则

| 项 | 规则 |
|---|---|
| 评分资格 | 学生；简历必须已核查；任职身份限在职 / 曾任职 / 实习过 |
| 维度 | 成长空间、薪酬福利、工作强度、面试体验、推荐意愿，各 1-5 分 |
| 综合分 | `(成长 + 薪酬 + 面试 + 推荐 + (6 - 强度)) / 5`，工作强度反向计分 |
| 正文 | ≥ 50 字；命中内容黑名单拒绝 |
| 去重 | 同一学生对同一企业、同一任职身份只能评价一次 |
| 展示门槛 | 已通过样本 < 3 条只显示「样本不足」，不展示数值 |
| 审核 | 先审后发；管理员在「内容审核 → 企业评分」处理 |
| 推荐联动 | 样本 ≥ 3 且综合分 ≥ 4 时，推荐算法加 3 分并输出「企业口碑 x.x/5」理由 |

### 4.2 企业侧边界

- 企业只能查看与回应，不能删除评价或反向刷分；
- 企业可对不实内容发起申诉，由管理员核实后处理；
- 评价不参与职位审核结论，只影响排序权重与展示。

## 5. 急招专区（FR-Q）

| 项 | 规则 |
|---|---|
| 设置资格 | 企业；职位必须为 `APPROVED` |
| 有效期 | 1-30 天，到期自动失效，可重新设置 |
| 比例上限 | 急招岗位不超过本企业在招岗位的 30%（至少允许 1 个） |
| 展示 | 独立「急招专区」页面 + 职位卡片「急招 · 剩 N 天」标签 |
| 检索 | `search_jobs(only_urgent=True)` 只返回 `urgent_until >= 今天` 的职位 |
| 企业操作 | 职位管理页设置 / 取消急招 |

---

## 6. 小任务兼职（FR-T）

| 项 | 规则 |
|---|---|
| 发布资格 | 企业资质与 HR 均通过 |
| 内容 | 标题 4-60 字、说明 ≥ 30 字、城市必填、招募人数 1-100 |
| 红线 | 关键词拦截刷单、押金、垫付、返利、拉人头、日结高薪等 |
| 审核 | 先审后发；管理员在「内容审核 → 小任务」处理 |
| 报名 | 学生登录即可报名；同任务不可重复报名；名额满后拒绝 |
| 资金 | 平台不托管资金、不参与结算，页面固定展示防诈骗提示 |
| 区隔 | 不进入投递与简历快照流程，不计入实习经历 |
| 企业操作 | 发布、查看报名名单、结束任务 |

## 8. 优先级与落地顺序

| 批次 | 功能 | 理由 |
|---|---|---|
| P0 第一批 | 急招专区、招聘效果看板 | 无 UGC、复用现有数据，风险最低 |
| P0 第二批 | 候选人智能匹配排序 | 复用学生推荐算法，直接提升企业效率 |
| P1 第三批 | 企业文化交流区 | 价值最大，需身份标签与内容审核队列 |
| P1 第四批 | 企业评分 | 复用文化区的审核与身份体系 |
| P1 第五批 | 小任务兼职 | 灰产风险最高，独立审核与关键词拦截 |
| P2 第六批 | 人才库、面试邀约、反馈模板 | 依赖前两批数据与通知能力 |

## 9. 数据模型

| 表 | 用途 | 关键约束 |
|---|---|---|
| `jobs.is_urgent` / `jobs.urgent_until` | 急招标记与到期日 | `is_urgent ∈ (0,1)`，到期日参与检索 |
| `culture_posts` | 企业文化帖 | 任职状态 CHECK、先审后发、匿名标记、官方回应字段 |
| `company_reviews` | 企业评分 | 五维 1-5 CHECK、`UNIQUE(user_id, company_id, employment_status)` |
| `micro_tasks` | 小任务 | 状态 CHECK、人数 1-100 |
| `task_signups` | 小任务报名 | `UNIQUE(task_id, student_id)` |
| `job_views` | 职位浏览去重 | `UNIQUE(job_id, student_id)` |

老库通过 `core/db.py` 的 `_migrate()` 自动补列，新增表使用 `CREATE TABLE IF NOT EXISTS`，可重复执行。

## 11. 核心指标

| 模块 | 指标 | 目标 / 护栏 |
|---|---|---|
| 文化社区 | 周发帖量、身份核验通过率、举报率、删除率 | 举报率 < 3% |
| 企业评分 | 参评企业覆盖率、平均样本数、恶意评分拦截数 | 在招企业覆盖率 ≥ 60% |
| 急招 | 急招岗位占比、企业响应达标率 | 占比 ≤ 30% |
| 小任务 | 任务发布量、报名率、投诉率 | 投诉率趋近 0 |
| 招聘看板 | 浏览→投递转化率、平均响应时长 | 响应时长持续下降 |
| 候选人匹配 | 匹配排序使用率、面试转化率 | 对比原始排序提升 |

## 12. 双方利益平衡与风控

| 主体 | 保护措施 |
|---|---|
| 求职者 | 身份标签、匿名发声、评分样本门槛、防诈骗提示、小任务关键词拦截 |
| 企业 | 官方回应权、评分不可删改、无评分不扣分、急招资格明确规则 |
| 平台 | 先审后发、前台匿名后台实名、阶梯处罚、内容黑名单、审核动作留痕 |

**通用红线**：匿名不等于免责；评分只做小权重排序且可解释；平台不碰资金；隐私与歧视内容零容忍。

### 13.1 验证结果

- 新增 25 条自动化用例（12 条功能 + 13 条边界 / 异常），全量 **146 passed**，四项质量门禁通过；

| 限制 | 说明 |
|---|---|
| 身份核验为「简历核查 + 自述」 | 未接入离职证明 / 在职证明上传，后续可扩展材料核验 |
