# 功能规格说明书（Spec）

> 项目：校招平台 CampusRecruit
> 文档版本：v1.0（2026-11-18）
> 对应流程：图 2 阶段 1「需求收集」+ 阶段 2「功能规格说明书」
> 读者：产品、开发、测试与项目评审人

---

## 1. 背景与问题

高校毕业生与招聘企业之间存在明显的信息不对称：

- 学生难以在一个可信渠道内找到经过审核的实习/校招岗位；
- 企业难以快速筛选有真实简历的学生；
- 平台缺少对“企业资质、HR 身份、职位真实性、简历真实性”的独立把关。

本项目用一个 Python + Streamlit 的轻量 Web 应用，把上述流程做成可运行、可演示、可测试的 MVP。

### 1.1 产品目标

| 目标 | 可衡量结果 |
|---|---|
| 三端可用 | 学生、企业、管理员登录后各自看到独立导航与页面 |
| 四层审核可追溯 | 企业资质、企业 HR、职位、简历均有独立状态与审核记录 |
| 主流程闭环 | 学生注册 → 完善简历 → 投递 → 企业处理 → 学生看到反馈 |
| 初学者可维护 | 页面、服务、数据三层职责清晰，单文件不超过约 250 行 |

### 1.2 非目标（本版本明确不做）

- 邮件 / 短信通知
- 在线支付、合同签署
- 移动端 H5、微信小程序
- 单点登录（SSO / OIDC）
- 对象存储、CDN
- 实时聊天、视频面试
- 多学校 / 多租户隔离
- 营业执照 OCR 自动识别
- REST 接口的公网托管（演示环境只部署 Streamlit；REST 在本机或自建 VPS/Docker 运行）

## 2. 角色与权限

### 2.1 角色定义

| 角色 | 说明 | 注册方式 |
|---|---|---|
| 游客 | 未登录用户 | — |
| 学生 | 求职方，维护简历并投递 | 自助注册 |
| 企业 | 企业管理员，发布职位并筛选候选人 | 自助注册，需平台审核 |
| 平台管理员 | 审核与运营方 | 仅由初始化脚本创建，不开放注册 |

### 2.2 权限矩阵

| 功能 | 游客 | 学生 | 企业 | 管理员 |
|---|---|---|---|---|
| 登录 / 注册 | ✅ | — | — | ✅（仅登录） |
| 浏览职位列表 | ❌ | ✅（仅已通过） | ✅（仅本公司） | ✅（全部） |
| 维护个人简历 | ❌ | ✅（仅本人） | ❌ | ❌ |
| 投递职位 | ❌ | ✅ | ❌ | ❌ |
| 查看投递反馈 | ❌ | ✅（仅本人） | ✅（仅本公司职位） | ✅（只读） |
| 企业资料维护 | ❌ | ❌ | ✅（仅本公司） | ✅（只读 + 审核） |
| 发布 / 修改职位 | ❌ | ❌ | ✅（需双审核通过） | ❌ |
| 企业资质审核 | ❌ | ❌ | ❌ | ✅ |
| 企业 HR 审核 | ❌ | ❌ | ❌ | ✅ |
| 职位审核 / 推荐 | ❌ | ❌ | ❌ | ✅ |
| 简历核查 | ❌ | ❌ | ❌ | ✅ |
| 查看平台统计 | ❌ | ❌ | ❌ | ✅ |

> 说明：所有“仅本人 / 仅本公司”的限制必须在**服务层**校验，不能只靠页面隐藏按钮。

## 3. 核心业务流程

### 3.1 四层独立审核

```text
企业注册
  └─ 第 1 层：企业资质审核（营业执照 / 统一社会信用代码）
  └─ 第 2 层：企业 HR 审核（HR 姓名 / 企业邮箱 / 在职证明）
        └─ 两层均通过后，企业才可发布职位
              └─ 第 3 层：职位审核（真实性 / 内容合规）
                    └─ 通过后进入学生职位广场

学生注册 → 维护简历 → 第 4 层：简历核查
  └─ 简历通过后，学生才可投递
        └─ 投递 → 企业查看 → 筛选 / 拒绝 / 录用 → 学生查看反馈
```

### 3.2 关键规则

| 编号 | 规则 |
|---|---|
| BR-01 | 企业资质与 HR 身份是两个独立状态，任一未通过都不能发布职位 |
| BR-02 | 职位发布、职位编辑后均需重新审核，状态回到 `PENDING` |
| BR-03 | 学生只有简历状态为 `VERIFIED` 时才能投递 |
| BR-04 | 同一学生对同一职位只能投递一次（数据库唯一约束） |
| BR-05 | 投递时保存简历快照，之后学生修改简历不影响企业已收到的版本 |
| BR-06 | 企业只能查看和处理投递到**本公司职位**的简历 |
| BR-07 | 管理员每次审核只能处理 `PENDING` 状态的记录，防止重复审核 |
| BR-08 | 被拒绝的企业 / 职位 / 简历可修改后重新提交，状态回到 `PENDING` |
| BR-09 | 所有写操作成功后页面刷新，并给出明确成功提示 |
| BR-10 | 账号被停用后无法登录，也无法通过旧会话继续操作 |

## 4. 用户故事与验收标准

> 验收标准统一使用 Given / When / Then 格式；每条都可在阶段 5 转化为测试用例。

### 4.1 账号与登录

#### US-01 学生 / 企业自助注册

**作为** 游客，**我希望** 选择角色注册账号，**以便** 进入对应端使用平台。

- **Given** 游客在注册页，**When** 选择“学生”，填写合法邮箱、姓名、不少于 8 位密码并提交，**Then** 创建学生账号并提示“注册成功，请登录”。
- **Given** 游客选择“企业”，**When** 填写企业名称、邮箱、密码并提交，**Then** 创建企业账号，同时生成一条 `PENDING` 的企业资料记录。
- **Given** 邮箱已被注册，**When** 再次提交，**Then** 提示“该邮箱已注册”，不创建重复账号。
- **Given** 注册页，**Then** 页面上不存在“管理员注册”入口。

#### US-02 登录、按角色进入、退出

**作为** 已注册用户，**我希望** 登录后只看到属于我角色的功能。

- **Given** 学生账号，**When** 输入正确邮箱和密码登录，**Then** 进入学生首页，导航只包含学生页面。
- **Given** 企业账号，**When** 登录，**Then** 进入企业首页，导航只包含企业页面。
- **Given** 管理员账号，**When** 登录，**Then** 进入管理端概览。
- **Given** 任意已登录用户，**When** 点击“退出登录”，**Then** 会话被清空并回到登录页，浏览器后退也不能恢复操作权限。
- **Given** 密码错误，**When** 提交，**Then** 统一提示“邮箱或密码错误”，不提示“邮箱不存在”。

### 4.2 学生端

#### US-03 维护个人简历

**作为** 学生，**我希望** 填写并保存简历，**以便** 申请职位。

- **Given** 已登录学生，**When** 首次填写姓名、手机号、学校、专业、毕业年份、技能并保存，**Then** 生成一条 `PENDING` 简历。
- **Given** 简历已存在，**When** 修改并保存，**Then** 更新内容，状态回到 `PENDING` 等待重新核查。
- **Given** 必填项为空或毕业年份不在 2000-2100，**When** 提交，**Then** 显示字段级错误，不写入数据库。

#### US-04 上传简历附件

**作为** 学生，**我希望** 上传 PDF/DOCX 简历附件，**以便** 企业下载查看。

- **Given** 学生上传 `pdf` 或 `docx` 且 ≤ 5 MB，**When** 提交，**Then** 文件保存到 `uploads/resumes/`，数据库记录服务端生成的文件名。
- **Given** 上传 `.exe`、`.zip` 或超过 5 MB 的文件，**When** 提交，**Then** 拒绝并提示允许的格式与大小。
- **Given** 学生替换附件，**Then** 新文件使用新的 UUID 文件名，旧文件不被复用。

#### US-05 搜索与筛选职位

**作为** 学生，**我希望** 按关键词、城市、类型筛选职位，**以便** 找到合适岗位。

- **Given** 职位广场，**Then** 只展示 `APPROVED` 且未关闭的职位。
- **Given** 输入关键词“Python”、选择城市“杭州”、类型“实习”，**When** 点击查询，**Then** 返回同时满足三个条件的职位。
- **Given** 无匹配结果，**Then** 显示空状态提示，而不是空白页面。
- **Given** 推荐职位存在，**Then** 列表按“推荐优先 + 发布时间倒序”排序。

#### US-06 投递职位

**作为** 学生，**我希望** 对职位投递简历，**以便** 获得面试机会。

- **Given** 简历为 `VERIFIED`、职位为 `APPROVED` 且未关闭，**When** 点击“投递”，**Then** 创建一条 `SUBMITTED` 投递记录，并保存简历快照。
- **Given** 简历不是 `VERIFIED`，**When** 点击投递，**Then** 提示“简历通过核查后才能投递”。
- **Given** 已投递过该职位，**When** 再次投递，**Then** 提示“请勿重复投递”。
- **Given** 职位已关闭，**Then** 不显示投递按钮，服务层同样拒绝。

#### US-07 查看投递结果与反馈

**作为** 学生，**我希望** 查看每条投递的当前状态和企业反馈。

- **Given** 学生有投递记录，**When** 打开“我的投递”，**Then** 按时间倒序展示职位、公司、状态、反馈、更新时间。
- **Given** 企业更新了状态或反馈，**When** 学生刷新页面，**Then** 看到最新结果。

### 4.3 企业端

#### US-08 提交企业注册资料

**作为** 企业管理员，**我希望** 提交企业与 HR 资料，**以便** 通过平台审核。

- **Given** 企业账号首次登录，**When** 填写企业名称、统一社会信用代码、HR 姓名、HR 企业邮箱，并上传营业执照与 HR 在职证明，**Then** 企业资质与 HR 审核状态均为 `PENDING`。
- **Given** 企业资料被拒绝，**When** 修改后重新提交，**Then** 对应状态回到 `PENDING`，并保留最近一次审核备注。
- **Given** 企业资料已通过，**Then** 页面展示“已通过”标识与审核时间。

#### US-09 发布职位

**作为** 企业管理员，**我希望** 发布校招/实习职位，**以便** 吸引学生投递。

- **Given** 企业资质与 HR 均为 `APPROVED`，**When** 填写职位名称、类型、城市、薪资、描述并提交，**Then** 创建 `PENDING` 职位。
- **Given** 任一审核未通过，**Then** 发布按钮不可用，并说明原因；服务层同样拒绝。
- **Given** 必填项缺失或职位描述少于 20 字，**When** 提交，**Then** 显示错误且不写库。

#### US-10 管理已发布职位

**作为** 企业管理员，**我希望** 查看、编辑、关闭职位。

- **Given** 职位为 `PENDING` 或 `APPROVED`，**When** 点击“关闭”，**Then** 状态变为 `CLOSED`，学生端不再展示。
- **Given** 职位被拒绝且企业修改内容，**Then** 状态回到 `PENDING` 重新审核。
- **Given** 职位为 `APPROVED`，**When** 企业修改职位内容，**Then** 状态回到 `PENDING`。
- **Given** 职位属于其他企业，**When** 通过篡改 URL 或参数访问，**Then** 服务层拒绝并提示无权限。

#### US-11 筛选候选人

**作为** 企业管理员，**我希望** 按职位、学校、专业、状态筛选投递者。

- **Given** 企业有投递记录，**Then** 只能看到投递到本公司职位的记录。
- **Given** 选择职位“后端开发实习生”、学校“浙江大学”、状态“待查看”，**When** 查询，**Then** 返回满足条件的候选人。
- **Given** 点击某候选人，**Then** 展示投递时的简历快照；若附件存在，可下载。

#### US-12 处理投递并给出反馈

**作为** 企业管理员，**我希望** 更新候选人状态并填写反馈。

- **Given** 状态为 `SUBMITTED`，**When** 企业点击“查看”，**Then** 状态变为 `VIEWED`。
- **Given** 状态为 `VIEWED`，**When** 企业选择“进入面试”并填写反馈，**Then** 状态变为 `SHORTLISTED`。
- **Given** 状态为 `SHORTLISTED`，**When** 企业选择“录用”，**Then** 状态变为 `HIRED`。
- **Given** 任意未结束状态，**When** 企业选择“不合适”，**Then** 状态变为 `REJECTED`，反馈必填。
- **Given** 状态为 `HIRED` 或 `REJECTED`，**When** 再次尝试变更，**Then** 服务层拒绝非法流转。

### 4.4 管理端

#### US-13 审核企业资质

**作为** 管理员，**我希望** 查看营业执照并批准或拒绝企业资质。

- **Given** 企业资质为 `PENDING`，**When** 管理员批准，**Then** 状态变为 `APPROVED`，记录审核时间与审核人。
- **Given** 管理员拒绝，**Then** 必须填写拒绝理由，状态变为 `REJECTED`。
- **Given** 记录已被其他管理员处理，**When** 再次提交审核，**Then** 提示“该记录已处理”，不覆盖结果。

#### US-14 审核企业 HR 身份

**作为** 管理员，**我希望** 独立审核企业 HR 身份。

- **Given** HR 状态为 `PENDING`，**When** 管理员批准或拒绝，**Then** 只改变 `hr_status`，不影响企业资质状态。
- **Given** HR 被拒绝，**Then** 拒绝理由必填，企业端可见。

#### US-15 审核与推荐职位

**作为** 管理员，**我希望** 审核职位并设置推荐。

- **Given** 职位为 `PENDING`，**When** 管理员批准，**Then** 状态变为 `APPROVED`，学生端可见。
- **Given** 管理员拒绝，**Then** 理由必填，企业端可见。
- **Given** 职位为 `APPROVED`，**When** 管理员开启“推荐”，**Then** 该职位在学生列表优先展示。
- **Given** 职位不是 `APPROVED`，**Then** 不能设置推荐。

#### US-16 核查学生简历

**作为** 管理员，**我希望** 核查简历真实性与完整性。

- **Given** 简历为 `PENDING`，**When** 管理员标记为“已核查”，**Then** 状态变为 `VERIFIED`，学生可以投递。
- **Given** 管理员拒绝，**Then** 理由必填，状态变为 `REJECTED`，学生端可见。
- **Given** 学生修改了已核查简历，**Then** 状态回到 `PENDING`，需要重新核查。

#### US-17 查看平台概览

**作为** 管理员，**我希望** 看到待办与核心数据。

- **Given** 管理员登录，**Then** 首页展示：待审企业资质数、待审 HR 数、待审职位数、待核查简历数、投递总数、已录用数。
- **Given** 点击任一指标，**Then** 跳转到对应审核页面。

## 5. 状态机

### 5.1 审核状态（企业资质 / HR / 职位 / 简历共用取值）

| 当前状态 | 允许动作 | 下一状态 | 操作人 |
|---|---|---|---|
| `PENDING` | 通过 | `APPROVED` / `VERIFIED` | 管理员 |
| `PENDING` | 拒绝（必填理由） | `REJECTED` | 管理员 |
| `REJECTED` | 修改后重新提交 | `PENDING` | 企业 / 学生 |
| `APPROVED` / `VERIFIED` | 修改内容 | `PENDING` | 企业 / 学生 |

### 5.2 职位状态

| 当前状态 | 允许动作 | 下一状态 |
|---|---|---|
| `PENDING` | 管理员通过 | `APPROVED` |
| `PENDING` | 管理员拒绝 | `REJECTED` |
| `REJECTED` | 企业修改后重提 | `PENDING` |
| `APPROVED` | 企业关闭 | `CLOSED` |
| `APPROVED` | 企业修改内容 | `PENDING` |
| `CLOSED` | 企业重新开放 | `PENDING` |

### 5.3 投递状态

| 当前状态 | 允许动作 | 下一状态 |
|---|---|---|
| `SUBMITTED` | 企业查看 | `VIEWED` |
| `SUBMITTED` | 企业拒绝 | `REJECTED` |
| `VIEWED` | 进入面试 | `SHORTLISTED` |
| `VIEWED` | 拒绝 | `REJECTED` |
| `SHORTLISTED` | 录用 | `HIRED` |
| `SHORTLISTED` | 拒绝 | `REJECTED` |
| `HIRED` / `REJECTED` | — | 终态，不可变更 |

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 本地环境、1,000 条职位数据下，筛选响应 < 1 秒 |
| 并发 | 面向演示与课程作业，支持 ≤ 20 个浏览器会话 |
| 数据一致性 | 写操作使用事务；投递唯一约束由数据库保证 |
| 安全 | 密码加盐哈希；参数化 SQL；服务层权限校验；上传白名单 |
| 可用性 | 所有列表具备空状态；所有表单有字段级错误提示 |
| 可维护性 | 页面 ≤ 250 行；服务函数单一职责；无循环依赖 |
| 可测试性 | 服务层不依赖 Streamlit，可在 pytest 中直接调用 |
| 接口交付 | 除 Streamlit UI 外，提供 FastAPI REST 适配层；接口契约以 `/openapi.json`（OpenAPI 3.1）为准，本地 `/docs` 可交互调试 |
| 接口认证 | REST 使用 JWT Bearer Token；角色与归属校验与 UI 完全一致（同用 `services/`） |
| 浏览器 | Chrome / Edge 最新版 |
| 语言 | 界面中文；代码标识符英文 |
| 时区 | 统一使用 `Asia/Shanghai`，数据库存 ISO 8601 字符串 |

## 7. 边界条件与异常

| 场景 | 期望行为 |
|---|---|
| 邮箱重复注册 | 提示已注册，不创建账号 |
| 密码错误 / 账号不存在 | 统一提示“邮箱或密码错误” |
| 账号被停用 | 拒绝登录，提示联系管理员 |
| 企业未双审通过就发布职位 | 页面禁用 + 服务层拒绝 |
| 简历未核查就投递 | 页面提示 + 服务层拒绝 |
| 重复投递同一职位 | 唯一约束 + 友好提示 |
| 上传超大 / 非法类型文件 | 拒绝并提示规则 |
| 审核已被处理的记录 | 检测状态后提示“已处理” |
| 访问他人资源 | 返回“无权限”，不泄露资源是否存在 |
| 数据库为空（首次运行） | 页面显示空状态，不报错 |
| 上传目录不存在 | 启动时自动创建 |
| 浏览器刷新 / 后退 | 登录态由 Session State 维护，权限不丢失 |

## 8. 验收定义（Definition of Done）

一个用户故事只有同时满足以下条件才算完成：

1. 页面可操作，主流程无阻塞。
2. 验收标准中的每条 Given/When/Then 都有对应测试或手工验证记录。
3. 服务层包含角色与归属校验。
4. 不出现明文密码、拼接 SQL、未限制的上传。
5. `ruff check .`、`python -m compileall .`、`pytest` 全部通过。
6. README 中的启动步骤可在干净环境复现。
7. 不引入本 Spec 之外的功能。
