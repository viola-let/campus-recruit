## 1. 测试目标与范围

本轮测试在原有 43 条开发阶段用例基础上，新增 70 条用例（66 条扩展测试 + 4 条模拟数据验证），目标如下：

1. 验证学生、企业、管理员三端核心业务闭环；
2. 验证输入边界、异常路径、权限隔离与状态机约束；
3. 验证并发写入下的一致性；
4. 验证 Spec 中“1,000 条职位下筛选 < 1 秒”的性能要求；
5. 验证分层依赖、版本锁定、页面规模等工程兼容性约束；
6. 验证模拟测试数据的规模、多样性、关联一致性、幂等性与真实数据隔离；
7. 输出可复现的缺陷清单与改进建议。

不在本轮范围：真实公网部署压测、多浏览器矩阵、渗透测试、邮件/短信等未实现功能。

## 7. 缺陷清单

### 7.1 本轮发现并已修复

#### BUG-01（P1）并发审核导致同一记录被重复处理

- **现象**：6 个管理员同时对同一条 `PENDING` 职位点击“通过”，6 次调用均返回成功，`review_logs` 写入 6 条记录。
- **影响**：违反 BR-07（只处理 `PENDING`）与 US-13（“该记录已处理”），审核结论可能被后写覆盖，审计记录失真。
- **涉及代码**：`services/jobs.py::review_job`、`services/students.py::review_resume`、`services/companies.py::_review`。
- **根因**：先 `SELECT status` 判断，再无条件 `UPDATE`，两个事务可同时通过检查。
- **修复**：改为条件更新 `UPDATE ... WHERE id = ? AND status = 'PENDING'`，用 `cursor.rowcount` 判断是否抢到处理权；只有更新成功才写审核日志。
- **回归用例**：TC-C03。
- **状态**：已修复。

#### BUG-02（P1）并发状态流转互相覆盖

- **现象**：同一投递在 `VIEWED` 状态下，被两个请求同时改为 `SHORTLISTED` 与 `REJECTED`，两次都成功。
- **影响**：状态机被绕过，最终状态取决于最后写入，可能出现“已拒绝又被录用”或相反结果，企业反馈与历史不一致。
- **涉及代码**：`services/applications.py::update_status`；同时加固 `services/jobs.py::close_job`、`reopen_job`。
- **根因**：读取旧状态后无条件更新。
- **修复**：条件更新 `WHERE id = ? AND status = <旧状态>`，`rowcount != 1` 时返回 `INVALID_STATE`。
- **回归用例**：TC-C04。
- **状态**：已修复。

### 7.2 待改进问题

| 编号 | 级别 | 问题 | 复现 / 证据 | 影响 | 建议 |
|---|---|---|---|---|---|
| DEF-03 | P2 | API 错误响应结构不统一 | 业务错误返回 `{code, message}`；401/403 由 `HTTPException` 返回 `{detail}` | 前端需写两套解析逻辑 | 注册统一异常处理器，覆盖 `HTTPException` 与 `RequestValidationError` |
| DEF-04 | P2 | 登录无频率限制与锁定 | 连续错误密码可无限尝试 | 存在暴力破解风险 | 按邮箱/IP 限流，连续失败锁定或增加验证码 |
| DEF-05 | P2 | JWT 签发后不可撤销 | 退出登录只清 Streamlit 会话；旧 Token 在 8 小时内仍有效 | 账号停用/泄露后无法立即失效 | 缩短 TTL + 刷新令牌，或增加用户级 `token_version` / `jti` 黑名单 |
| DEF-06 | P2 | 上传只校验后缀与大小 | 仅检查 `.pdf/.docx` 和 5 MB；未校验 MIME/文件头；超限映射 400 | 可上传伪装文件；语义上应为 413 | 增加魔数校验；`FILE_TOO_LARGE → 413`；可选病毒扫描 |
| DEF-07 | P3 | 修改企业资料会同时重置资质与 HR 状态 | 只改企业名称也会把双状态置为 `PENDING` | 产生不必要的人工复审 | 按字段分组送审，或拆分“企业信息 / HR 信息”两张表单 |
| DEF-08 | P3 | 搜索关键词未转义 LIKE 通配符 | 搜索 `%` 返回全部职位 | 搜索结果与用户预期不符 | 转义 `%`、`_`，或改用 FTS5 全文检索 |
| DEF-09 | P3 | 列表只有 limit，没有分页 | 最多返回 200 条，无总数与页码 | 数据增长后无法浏览完整数据 | 增加 `page/page_size/total` 契约与页面分页控件 |
| DEF-10 | P3 | SQLite 单写者，未启用 WAL | 高并发写可能 `database is locked` | 写入吞吐受限 | 开启 WAL 与 `busy_timeout`；生产环境评估 PostgreSQL |
| DEF-11 | P3 | 投递与职位下架存在竞态窗口 | 校验职位 `APPROVED` 后、插入前职位被关闭 | 可能产生已关闭职位的投递 | 用事务 + 条件插入，或插入前再次校验职位状态 |
| DEF-12 | P3 | 投递状态变更无独立审计日志 | 只有 `review_logs`，没有投递状态历史 | 无法追溯谁在何时改了状态 | 新增 `application_status_logs` 表 |
| DEF-13 | P3 | 无邮箱验证、找回密码、双因素 | 注册后可直接使用；忘记密码无入口 | 账号安全与可恢复性不足 | 增加邮箱验证、重置密码流程；管理员支持 MFA |
| DEF-14 | P4 | 浏览器兼容矩阵不完整 | 仅 Chromium 内核实测；未测 Firefox/Safari/移动端 | 跨端显示与交互存在未知风险 | 引入 Playwright 多浏览器回归；补充移动端断点 |
| DEF-15 | P4 | 缺少可观测性 | 无结构化日志、指标、错误追踪 | 线上问题定位困难 | 增加请求 ID 日志、健康检查、Prometheus/Sentry |
| DEF-16 | P4 | 无数据导出与运营报表 | 管理员只能看当前指标 | 运营分析能力弱 | 增加 CSV 导出与趋势统计 |

## 8. 改进建议（按优先级）

### P0｜上线前必须处理

1. 统一 REST 错误响应结构，避免前端两套解析。
2. 登录限流与失败锁定，防止暴力破解。
3. JWT 撤销机制或缩短有效期。
4. 上传文件做魔数校验，超限返回 413。
5. SQLite 开启 WAL 与 `busy_timeout`，降低并发写锁冲突。

### P1｜近期迭代

1. 列表分页与总数返回。
2. 投递状态审计日志。
3. 企业资料分模块送审，减少无效复审。
4. LIKE 通配符转义或引入 FTS5。
5. 邮件通知（投递状态变化、审核结果）。

### P2｜中期增强

1. 密码找回、邮箱验证、管理员 MFA。
2. 面试安排与候选人日程。
3. 企业子账号与细粒度权限。
4. 数据导出、趋势报表。
5. 结构化日志、指标与错误追踪。
6. Playwright 多浏览器与移动端回归。

## 9. 测试限制与结论

### 9.1 限制

- 并发测试使用线程模拟，未覆盖多进程、多实例与真实网络延迟；
- 性能数据来自本地 SQLite 单机环境，不代表公网部署表现；
- 浏览器兼容性仅覆盖 Chromium 内核，未执行 Firefox/Safari/移动端矩阵；
- 未进行专业渗透测试，仅覆盖功能级安全边界；
- 公网部署、二维码与 Git 标签尚未执行。

### 9.2 结论

- 113 条自动化用例全部通过，四项质量门禁通过；
- 三端核心业务闭环、权限隔离、状态机与 REST 契约均验证可用；
- 本轮发现 2 个 P1 并发一致性缺陷，均已修复并由回归用例锁定；
- 剩余问题以安全加固、可扩展性与可观测性为主，不阻塞课程演示与本地验收；
- 建议按 P0 → P1 → P2 顺序迭代，再执行公网部署与多浏览器回归。
